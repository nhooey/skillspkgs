# pkgs/

Curated per-skill flake wrappers around third-party Agent Skills hosted in upstream repositories.

Each wrapper folder is a **standalone Nix flake** that pins one upstream repo and delegates all the build/install/uninstall logic to [`nhooey/agent-skill-flake`](https://github.com/nhooey/agent-skill-flake) via `lib.mkSkillFlake` (or `lib.mkAllSkillsFlake` for [multi-skill upstreams](#multi-skill-upstreams)). There is no aggregator at the root of this repo — each wrapper stands on its own.

## What this collection is for

Upstream skill projects whose authors don't ship a Nix flake themselves and won't accept a Nix-related PR. The wrapper here is the smallest possible flake that pins the upstream by `(github:<owner>/<repo>, rev, hash)` and lets `agent-skill-flake` produce the install / uninstall / preview / reap apps.

## What this collection is **not** for

PRs that fall under any of these get closed:

- **First-party skill content.** Don't put a `SKILL.md` directly under `pkgs/<name>/` and ship the words in this repo. If you want to maintain skill content, ship it in its own GitHub repo or use [`nhooey/nix-skills`](https://github.com/nhooey/nix-skills); then submit a wrapper here.
- **Forks of upstream skills with local edits.** If you need to patch upstream behaviour, fix it upstream or maintain a fork in your own repo and wrap *that* repo.
- **Skills that aren't reachable as a `fetchFromGitHub` snapshot.** If the source can't be pinned by `(owner, repo, rev, hash)`, it doesn't belong here.

## Layout

```
pkgs/
├── README.md           # this file
└── <skill-name>/
    ├── flake.nix       # one wrapper, ~20 lines
    └── flake.lock      # generated by `nix flake lock`
```

A single-skill wrapper intentionally has **no `default.nix`** — its `flake.nix` is the single source of truth, with the upstream pin (`owner`, `rev`, `hash`) in the `inputs` block and the generated `flake.lock`. (Multi-skill wrappers add a bespoke `default.nix` — see [Multi-skill upstreams](#multi-skill-upstreams).)

## What `flake.nix` should look like

```nix
{
  description = "<one-line description of the skill, mentioning the upstream repo>";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    agent-skill-flake.url = "github:nhooey/agent-skill-flake";
    agent-skill-flake.inputs.nixpkgs.follows = "nixpkgs";
    <skill>-src = {
      url = "github:<upstream-owner>/<upstream-repo>/<commit-sha>";
      flake = false;
    };
  };

  outputs = { nixpkgs, agent-skill-flake, <skill>-src, ... }:
    agent-skill-flake.lib.mkSkillFlake {
      inherit nixpkgs;
      skillName = "<skill-name>";  # must match upstream SKILL.md frontmatter `name:`
      src = <skill>-src;
    };
}
```

Then run `nix flake lock` inside the wrapper directory to generate the lockfile.

`mkSkillFlake` ships only `SKILL.md`, `references/`, and `scripts/` from `src`; everything else (LICENSE, README.md, the upstream's own flake.nix if any) is filtered out. If the upstream skill needs more files than that to function, this lib (and therefore this collection) is not the right tool.

## Multi-skill upstreams

Some upstreams ship many skills in one repo (`daymade`, `superpowers`, `trailofbits`, `caveman`). These don't use the single-skill template above. Each gets a bespoke `pkgs/<name>/default.nix` that calls `agent-skill-flake.lib.mkAllSkillsFlake`, plus a thin `flake.nix` that re-exports its `packages` for the standalone `?dir=pkgs/<name>` face. `pkgs/superpowers/` and `pkgs/daymade/` are worked examples. The recipe:

- **Point `mkAllSkillsFlake` at the tree root and let it recurse.** `discoverSkills` descends through grouping directories and treats any directory holding a `SKILL.md` as a leaf, so a single call finds every skill — no per-suite loop. Root it at whichever directory contains the skills: `${src}/skills` for a flat `skills/<skill>/` layout, or `${src}/plugins` for a plugin-marketplace layout like `trailofbits/skills` (`plugins/<plugin>/skills/<skill>/`). When a repo ships several parallel copies of its skills, root at the most complete tree.
- **Set `source.owner` to the lowercased GitHub username.** It becomes the package-key namespace (`agent-skill-<owner>-<skill>`), so two upstreams' same-named skills don't collide. The namespace validator rejects anything outside `^[a-z0-9][a-z0-9-]*$`, so `JuliusBrussee` is passed as `juliusbrussee`.
- **Re-add referenced content the whitelist drops.** `mkAllSkillsFlake` ships only `SKILL.md`, `references/`, and `scripts/`. If a skill keeps material elsewhere — e.g. `trailofbits/skills` uses `resources/` and loose companion `.md` files — pass `extraDirs` / `extraFiles` to ship it.
- **Register the source in both `srcs` maps.** Add the `*-src` input and its `srcs` entry to the root [`flake.nix`](../flake.nix) — and to that file's `infrastructureInputs` list, so it isn't mistaken for an aggregated category-2 repo — *and* to this directory's standalone [`flake.nix`](./flake.nix). `pkgs/default.nix` auto-discovers every `pkgs/<name>/` subdir and forces `srcs.<name>`, so a wrapper missing from either map breaks that face with `attribute '<name>' missing`.

## Pinning rules

- Always pin to a **commit SHA**, never a branch or tag — branches move and tags can be re-pointed.
- The pin lives in two places: the `humanizer-src.url`'s `/<sha>` segment in `flake.nix`, and the `narHash` in `flake.lock`. Both must agree; `nix flake lock` enforces this.
- When you bump the pin, bump the lockfile in the same commit. One PR per wrapper.

## Computing the hash

`nix flake lock` does it for you the first time. To bump:

```bash
cd pkgs/<skill-name>
nix flake update <skill>-src
git add flake.lock
```

## Review

`/pkgs/` has no CODEOWNER, so PRs adding or bumping wrappers don't auto-request review. That's deliberate — third-party additions are open contribution territory.
